# 도메인 정책 (policies.md)

> 차감·예약·상태에 관한 모든 규칙의 최종 기준 문서.
> 코드 구현이 이 문서와 다르면 코드가 틀린 것이다.

## 1. 이용권 3종

| 이용권        | 코드                 | 결제 단위     | 이용 방식                                         |
| ------------- | -------------------- | ------------- | ------------------------------------------------- |
| 저녁반 회비   | `EVENING_MEMBERSHIP` | 1 / 3 / 6개월 | 기간 내 저녁반(단체수업) 무제한 참여, 예약 불필요 |
| 예약제 횟수권 | `SESSION_PASS`       | 횟수          | 예약제 수업(SESSION)을 예약해 참여, 1회 차감      |
| 1:1 레슨권    | `LESSON_PASS`        | 횟수          | 1:1 레슨(LESSON)을 예약해 참여, 1회 차감          |

- 모든 결제는 오프라인. 관리자가 시스템에 수기 등록한다.
  - 등록 시 **시작일을 지정할 수 있다** (기본값 오늘, 과거 날짜 허용) — 수기 등록이라 결제·이용 시작 시점과 등록 시점이 다를 수 있다 (D-055)
  - 횟수권 초기 횟수는 **0.5 단위 자유 입력**. 초기 부여도 `INITIAL_GRANT` 이력으로 남는다 (D-055)
- 한 회원이 여러 이용권을 동시 보유할 수 있다.
- `SESSION_PASS`, `LESSON_PASS` 유효기간: **시작일로부터 1년** (D-055).
  관리자가 유효기간을 수정할 수 있다 — 만료 후 서비스 부여 등 대응 (D-056)
- `EVENING_MEMBERSHIP` 기간(1/3/6개월)은 **시작일 기준**으로 계산하며, 관리자가 수정(연장)할 수 있다 (이벤트, 휴회 보상, 추가 결제)
- 유효기간·회비 기간의 **종료일은 그 날짜 당일까지 사용 가능**하다 — `endDate = startDate.plusYears(1)/plusMonths(개월수).minusDays(1)`, 유효 판정 `!today.isAfter(endDate)` (D-066)
- 기간·유효기간 변경은 **변경 전값/후값/사유/주체/시각**이 `PassPeriodChange` 이력으로 남는다 (D-057)
- **오등록 정정**: 관리자가 이용권 등록을 취소할 수 있다 — 물리 삭제가 아닌 **취소 상태 전환** + `REGISTRATION_CANCELED` 이력(횟수권은 잔여를 0으로 상쇄).
  취소된 이용권은 회원 화면에서 숨기고, 관리자 화면에서는 구분 표시한다 (D-059)

## 2. 시간표 (송파점 기준)

- 모든 타임은 **90분** 단위
- 저녁반: 월~금 19:00–20:30, 21:00–22:30
- 예약제 수업: 화·목·금 11:00–12:30, 13:00–14:30 / 토·일 09:00, 11:00, 13:00, 15:00, 17:00 시작 5타임
- **1:1 레슨**: 체육관 운영 중인 모든 타임슬롯에 예약 가능.
  저녁반·예약제 수업과 **같은 타임에 동시 진행 가능** (코치 2명 체제).
  단, 1:1은 **타임당 1명**만 예약 가능.

## 3. 예약 규칙

- **오픈**: 해당 주 월요일에 그 주(월~일) 전체 예약이 열린다. 다음 주 예약은 불가.
- **마감**: 수업 시작 시각 전까지 예약 가능 (별도 마감 없음)
- **정원**: 예약제 수업 10명 (지점/수업별 설정 가능하게 구현), 1:1 레슨 1명
- **회원의 취소/변경**:
  - 취소 = 예약 삭제 + 차감 복구
  - 변경 = 기존 예약 취소 + 다른 타임 재예약으로 처리
  - **당일에는 취소도 변경도 불가** (변경 허용 시 당일취소 우회 가능하므로)
- **관리자의 취소/변경**: 당일 포함 제약 없음. 취소 시 차감 복구 여부 선택 (기본: 복구)
- **노쇼**: 별도 처리 없음 — 예약 시 이미 차감되었으므로 그대로 확정. 출석 기록에만 불참으로 남는다.
- **잔여 부족**: 잔여 횟수가 차감량보다 적으면 예약 자체가 불가 (잔여 0.5회로는 1회짜리 예약 불가)

## 4. 차감 규칙

### 4.1 즉시 차감 원칙

- **예약 성공 시 즉시 1회 차감. 취소(회원 당일 전 취소, 관리자 취소-복구 선택, 휴강)로 예약이 사라지면 즉시 복구.**
- 회원이 보는 잔여 횟수는 항상 실제 사용 가능 횟수와 일치해야 한다.
- 모든 차감/복구는 이력 테이블에 기록: (이용권, ±수량, 사유 코드, 발생 주체, 시각)
  - 사유 코드 예: `RESERVE`, `CANCEL_REFUND`, `ADMIN_ADJUST`, `EVENING_HALF`, `INACTIVITY`, `CLASS_CANCELED_REFUND`, `INITIAL_GRANT`, `REGISTRATION_CANCELED`

### 4.2 저녁반 0.5회 참여 (횟수권 회원)

- `SESSION_PASS` 보유 회원은 **0.5회 차감으로 저녁반 참여** 가능
- 사전 예약 불필요. 현장 확인 후 **관리자가 수동으로 0.5회 차감**한다.
- 잔여 0.5회면 저녁반 0.5회 참여만 가능

### 4.2a 관리자 수동 가감 (ADMIN_ADJUST — D-056)

- 가감 단위는 **0.5**, 사유 입력 필수
- **결과 잔여가 음수가 되는 가감은 거부**한다
- 유효기간이 **만료된 횟수권에도 가감 가능** — 유효기간 수정 기능과 세트로 만료 후 서비스 부여에 대응
- 기간제(`EVENING_MEMBERSHIP`)는 횟수 가감 대상이 아니다 — 기간 수정으로만 조정

### 4.3 2주 미사용 자동 차감 (SESSION_PASS 대상)

- 기준일로부터 **2주 경과 시 1회 차감, 이후 2주마다 반복** (4주 미사용 = 2회)
- 기준일: **마지막 출석일과 마지막 예약의 수업일 중 더 최근 날짜**. 둘 다 없으면 **등록일** (D-027)
  - 출석은 관리자 수동 참고 데이터라 체크 누락 시 부당 차감이 발생할 수 있고,
    예약은 이미 차감된 '사용'이므로 미사용으로 간주하면 모순이다
- 예외 (차감하지 않음):
  - 회원 상태가 `휴회(ON_LEAVE)`인 기간
  - 잔여 횟수 0
  - 유효기간(1년) 만료된 이용권
- 구현: **매일 새벽 배치**. 반드시 멱등하게 — 같은 날 배치가 중복 실행돼도 이중 차감 금지.
  (예약 관련 차감은 §4.1의 실시간 트랜잭션, 정책성 차감은 배치로 역할 분리)

## 5. 회원 상태

| 상태     | 코드       | 설명                                                                  |
| -------- | ---------- | --------------------------------------------------------------------- |
| 승인대기 | `PENDING`  | 카카오 가입 직후. 승인 대기 화면만 노출                               |
| 활성     | `ACTIVE`   | 정상 이용                                                             |
| 휴회     | `ON_LEAVE` | 관리자가 설정. 2주 미사용 차감 정지. 저녁반은 기간 연장으로 별도 보상 |
| 비활성   | `INACTIVE` | 탈퇴/장기 미이용 등                                                   |

### 5.1 가입·온보딩

- 카카오 로그인은 **인증 수단으로만** 사용한다 — 기본 제공 정보만 받는다 (실명·전화번호는 카카오에서 수집하지 않음)
- 최초 로그인 시 온보딩 화면에서 **실명·전화번호를 필수 입력**받는다 (전화번호 형식 검증)
- 온보딩 미완료는 별도 회원 상태가 아니다 — `PENDING` 상태에서 **프로필(이름·전화번호) 입력 여부**로 판정한다
- 관리자 승인 목록에는 **프로필이 입력된 PENDING 회원만** 노출한다
- 회원 관리·식별의 기준은 **이름 + 전화번호**다
- 비즈앱 전환·동의항목 심사 통과 후 카카오 자동 수집(온보딩 폼 자동 채움)은 v2 (D-025)

### 5.2 승인·거절·상태 전이 (D-034)

- **승인**: 관리자가 승인하면 `PENDING` → `ACTIVE`
- **거절**: 별도 상태를 추가하지 않는다 — `PENDING` → `INACTIVE` 전환 + **거절 사유 기록**
- 거절된 회원이 재로그인하면 **거절 안내 화면 대상으로 식별**된다 (기능 접근은 §5 상태 규칙에 따라 불가)
- **재신청**: 회원 셀프 재신청은 없다 — 관리자가 상태를 `PENDING`으로 되돌리는 운영 방식
- **승인 취소**: 별도 기능 없이 관리자의 상태 변경(`ACTIVE` → `ON_LEAVE`/`INACTIVE`)으로 갈음한다

## 6. 출석 체크

- **모든 수업**(저녁반/예약제/1:1)에 대해 관리자가 타임별 참여자 명단을 체크한다.
- 출석 기록은 **차감과 무관한 참고용 데이터**다. (차감은 예약 시점에 이미 확정)
  - 예약했지만 불참한 경우: 차감 유지 + 출석 기록만 불참
  - 목적: 명단 관리, 참여율 확인, 횟수 문의 대응
- 예외적으로 저녁반 0.5회 차감(§4.2)만 출석 확인과 함께 관리자가 수동 처리한다.
- 2주 미사용 차감(§4.3)의 기준일 중 "마지막 출석일"은 이 출석 기록을 기준으로 한다
  (기준일은 마지막 예약의 수업일과 비교해 더 최근 날짜를 쓴다 — §4.3).

## 7. 휴강 처리

- 관리자가 특정 날짜의 특정 수업을 휴강 처리할 수 있다 (공휴일, 이벤트 등)
- 휴강 시: 해당 타임 기존 예약 전부 자동 취소 + 차감 복구 + 알림 생성
- 휴강된 타임은 회원 예약 화면에서 예약 불가로 표시

## 8. 동시성 요구

- 정원 마지막 자리에 대한 동시 예약, 1:1 슬롯에 대한 동시 예약에서 **초과 예약 0건**
- DB 유니크 제약 + 락(또는 조건부 insert)으로 보장하고, k6 부하테스트로 검증한다.
