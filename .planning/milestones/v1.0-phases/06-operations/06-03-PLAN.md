위치는 기존 `reservationRepository` 옆(도메인 조회 리포지토리 묶음)으로 하고, `attendance` 패키지를

`runStarted`의 `if (memberIds.isNotEmpty())` 블록 안, 기존 `lastActiveReservationClassDates` 선언
바로 위에 `lastAttendedClassDates` 지역 변수를 추가한다 — `attendanceRepository.findLastAttendedClassDates(memberIds)`를
`associate { it.getMemberId() to it.getDate() }`로 맵으로 만든다(`MemberDateProjection`이므로
`toSeoulLocalDate()` 변환이 필요 없다 — `classDate`가 이미 `LocalDate`다).

`InactivityDueDateCandidates` 생성부의 `lastAttendanceDate = null`과 그 위의
"Phase 6이 Attendance를 도입하면 여기에 값을 채운다(D-105 후보 ①)" 주석을 제거하고
`lastAttendanceDate = lastAttendedClassDates[memberId]`로 교체한다. 주석은 대신
"후보 ①은 `ATTENDED`만 인정한다(policies §6) — 불참은 미사용이다"로 바꿔 남긴다.

**추가로 하지 않을 것(명시적 금지)**: 소급 출석이 이미 실행된 `INACTIVITY` 차감을 되돌리는 어떤

환불하는 경로를 추가하지 않는다 — `InactivityDueDateCalculator.shortfall`의 `coerceAtLeast(0)`가
이미 음수 부족분을 0으로 눌러 "되돌리지 않음"을 보장한다. 정정이 필요하면 관리자 `ADMIN_ADJUST`가
유일한 경로다.
