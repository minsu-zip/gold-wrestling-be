    `data class InactivityDueDateCandidates(lastAttendanceDate: LocalDate?, lastActiveReservationClassDate: LocalDate?, returnedFromLeaveDate: LocalDate?, lastSessionPassRegistrationDate: LocalDate?, lastPositiveAdjustDate: LocalDate?)`
    — 값 객체이므로 `data class` 허용(엔티티 금지 규약은 JPA 엔티티 전용, `WeekRange` 선례 D-04-04).

    · `resolveDueDate(candidates): LocalDate?` — 후보 중 non-null의 max. 전부 null이면 null.
    · `expectedDeductionCount(dueDate: LocalDate, today: LocalDate): Int` — `floor(경과일 / 14)`, 경과일이 음수면 0.
    · `shortfall(dueDate: LocalDate, today: LocalDate, inactivityEventDates: List<LocalDate>): Int`
      — `expectedDeductionCount − (inactivityEventDates 중 dueDate 이후(당일 포함) 건수)`, 하한 0.

    **resolveDueDate 케이스**
    · 후보 5개 전부 null → null (판정 대상 아님 — 호출부가 스킵한다)
    · 출석일만 null이고 나머지 4개가 있으면 그 4개 중 max를 고른다 (Phase 6 전의 자연 부재)
    · 복귀일이 가장 최근이면 복귀일이 기준일이다 ("복귀하면 2주 유예가 새로 시작", D-105)
    · +가감일이 가장 최근이면 +가감일이 기준일이다 ("충전 시점부터 새로 시작")
    · 등록일만 있는 신규 회원(예약·복귀·가감 없음) → 등록일이 기준일이다
    · 같은 날짜가 두 후보에 있으면 그 날짜가 기준일이다 (동률에 예외 처리 없음)

    **expectedDeductionCount 케이스 (policies §4.3 "2주 경과 시 1회, 이후 2주마다")**
    · 경과 0일 → 0 · 13일 → 0 · **14일 → 1** · 27일 → 1 · **28일 → 2** · 41일 → 2 · 42일 → 3
    · 기준일이 오늘보다 미래(경과 음수) → 0 (미래 수업일을 예약해 둔 회원이 음수 차감을 받지 않는다)

    **shortfall 케이스 (D-106 상태 기반 = 멱등 + 캐치업)**
    · 경과 14일, 이력 0건 → 1
    · 경과 14일, 이력 1건(기준일 이후) → **0** — 같은 날 두 번째 실행이 이중 차감하지 않는다(BATCH-04)
    · 경과 42일, 이력 0건 → **3** — 배치가 6주 밀렸다가 실행되면 밀린 주기를 몰아서 차감한다
    · 경과 42일, 이력 1건 → 2
    · 이력 날짜가 **기준일보다 이전**이면 세지 않는다 (기준일이 리셋되면 그 전 이력은 무관하다)
    · 이력 날짜가 **기준일 당일**이면 센다 (경계 — `!date.isBefore(dueDate)`)
    · 이력이 기대 횟수보다 많으면 0을 반환한다 (음수 금지 — 수동 데이터 조작·마이그레이션 오류 방어)
    · 이력 리스트가 비어 있고 경과 13일 → 0
