**TokenPair.kt** — 값 객체. `data class TokenPair(accessToken: String, refreshToken: String, accessTokenExpiresAt: OffsetDateTime, refreshTokenExpiresAt: OffsetDateTime)`.
엔티티가 아니므로 `data class` 금지 규칙(conventions §3)은 적용되지 않는다 — 그 이유를 KDoc 한 줄로 남긴다.

**AuthExceptions.kt** — `DomainException`을 상속하는 인증 예외를 모아 둔다.
- `class RefreshTokenInvalidException(message: String = "다시 로그인해 주세요.") : DomainException(ErrorCode.REFRESH_TOKEN_INVALID, message)`
사용자 대면 문구만 담는다 — "만료됨/폐기됨/재사용 감지됨"을 응답에서 구분하지 않는다. 구분은 서버 로그로만 남긴다
(공격자에게 어느 토큰이 DB에 존재했는지 알려주지 않기 위해). 이 의도를 KDoc에 남긴다.

**TokenService.kt** — `@Service`, 클래스에 `@Transactional(readOnly = true)`, 변경 메서드에만 `@Transactional` (D-020).
생성자 주입: `JwtEncoder`, `RefreshTokenRepository`, `MemberRepository`, `AdminRepository`, `JwtProperties`, `Clock`.

- `private fun issueAccessToken(principalType, principalId, issuedAt): Pair<String, OffsetDateTime>`
  `JwtClaimsSet.builder()`에 `issuedAt`, `expiresAt`(=issuedAt + accessTokenExpiryMinutes), `subject(principalId.toString())`,
  `claim("principalType", principalType.name)`을 넣고 `JwsHeader.with(MacAlgorithm.HS256)`로 서명한다.
  **회원 상태(`status`)를 클레임에 넣지 않는다** — D-033이 명시적으로 금지한다. 그 이유를 KDoc 한 줄로 남긴다.
- `private fun generateRefreshTokenValue(): String` — `java.security.SecureRandom`으로 32바이트를 뽑아
  `Base64.getUrlEncoder().withoutPadding()`로 인코딩한다. `Random`/`Math.random`을 쓰지 않는다.
- `private fun hash(raw: String): String` — `MessageDigest.getInstance("SHA-256")` 결과를 소문자 hex 64자로 변환한다.
- `@Transactional fun issueTokenPair(principalType, principalId): TokenPair`
  현재 시각을 `OffsetDateTime.now(clock)`으로 얻고, access 발급 + refresh 원문 생성 + `RefreshToken` 엔티티 저장
  (주체에 따라 `member` 또는 `admin` 한쪽만 채운다 — D-037). 주체 조회 실패 시 `IllegalStateException`.
  반환하는 `TokenPair`에는 refresh **원문**을 담는다(저장은 해시).
- `@Transactional fun rotate(rawRefreshToken: String): TokenPair`
  해시로 행을 찾고, 없으면 `RefreshTokenInvalidException`.
  **찾은 행이 이미 폐기됐으면**: 재사용으로 간주해 그 주체의 미폐기 refresh를 전부 폐기한 뒤
  `RefreshTokenInvalidException`을 던진다. 이때 `logger.warn`으로 principalType/principalId를 남긴다(토큰 값은 남기지 않는다).
  만료됐으면 그 행만 폐기하고 예외.
  정상이면 그 행을 `revoke(now)`하고 같은 주체로 `issueTokenPair`를 호출해 새 쌍을 만든다.
- `@Transactional fun revoke(rawRefreshToken: String)` — 해시로 찾아 있으면 `revoke(now)`. 없으면 조용히 반환(멱등).
- `@Transactional fun revokeAllForMember(memberId: Long)` — `MemberRepository`로 회원을 찾고
  `findAllByMemberAndRevokedAtIsNull`의 각 행에 `revoke(now)`. 회원이 없으면 조용히 반환.
  (관리자용 전량 폐기는 이번 phase에 소비자가 없으므로 만들지 않는다 — 필요해지는 플랜에서 추가한다.)
