`pass/PassRepository.kt`의 기존 후보 조회(정렬·비교축을 그대로 물려받는다):
```
@Query("select p from Pass p where p.member.id = :memberId and p.type = :type " +
    "and p.status = com.goldwrestling.pass.PassStatus.ACTIVE " +
    "and p.endDate >= :classDate and p.remainingCount >= :requiredAmount " +
    "order by p.endDate asc, p.id asc")
fun findDeductionCandidates(memberId, type, classDate, requiredAmount): List<Pass>
```
`endDate >= :날짜`가 `Pass.isExpired`(D-066 종료일 포함)와 같은 비교축이다 — 배치 쿼리도 이 축을 쓴다.

엔티티 필드(직접 확인 완료):
- `Pass`: `member`, `type: PassType`, `status: PassStatus`, `startDate`, `endDate: LocalDate`,
  `remainingCount: BigDecimal?`, `createdAt: OffsetDateTime`(등록일 — **`startDate` 아님**, D-105)
- `Reservation`: `member`, `classDate: LocalDate`(비정규화 컬럼), `status: ReservationStatus`(ACTIVE/CANCELED)
- `PassTransaction`: `pass`(→ `pass.member`), `amount: BigDecimal`, `reason: TransactionReason`,
  `occurredAt: OffsetDateTime`
- `Member`: `status: MemberStatus`(PENDING/ACTIVE/ON_LEAVE/INACTIVE), `returnedFromLeaveAt: OffsetDateTime?`(05-02)

`TransactionReason`: `RESERVE`, `CANCEL_REFUND`, `ADMIN_ADJUST`, `EVENING_HALF`, `INACTIVITY`,
`CLASS_CANCELED_REFUND`, `INITIAL_GRANT`, `REGISTRATION_CANCELED`.

IN절 벌크 조회 관례: `reservation/ReservationRepository.findAllByClassSessionIdInAndStatusWithMember`
(`@Query` + `@Param`, `Collection<Long>` 파라미터).

**GROUP BY + 스칼라 프로젝션은 이 저장소에 선례가 없다** — 05-RESEARCH가 인터페이스 프로젝션 문법을
미검증으로 표시했다. Task 1에서 `verify-boot4-api` 절차로 먼저 확인한다.

테스트: `@SpringBootTest` + `@Import(TestcontainersConfiguration::class, TestClockConfiguration::class)`,
