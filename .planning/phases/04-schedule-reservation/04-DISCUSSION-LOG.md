## 사용자가 마지막에 직접 정리한 3건

**1. 등록 취소(PASS-08) 대상 이용권에 활성 예약이 있는 경우 — 정책 구멍이었음**
사용자 제안 그대로 확정: 활성 예약이 있으면 **등록 취소를 거부**하고, 관리자가 예약을 먼저
정리(대리 취소, 복구 안 함)한 후 취소한다. **자동 연쇄 취소는 만들지 않는다** — 오등록 정정은
드문 운영 행위라 명시적 절차가 안전하다. → `docs/policies.md` §1에 반영 완료 (D-089).

**2. RESV-07·08**
- 관리자 예약 조회: 기간(날짜 범위)·수업 종류·회원 검색어 필터 + `page`/`size` 페이지네이션
  (기존 목록 API들과 동일 형태)
- 대리 취소의 "복구 안 함" 옵션 **유지** — 대표 사용처는 **당일 불참 연락**. 회원은 당일 취소가
  불가하니 관리자가 대신 취소하되 정책상 차감은 유지해야 한다
- 관리자의 **정원 무시(오버부킹)는 만들지 않는다** — "초과 예약 0건"이 Core Value인 시스템에
  백도어를 두지 않는다. 정원 10이 실수요 대비 여유가 있어 실익도 없다

**3. SCHED-03 데이터 형태**
- 주간 보드 API는 그리드 요약을 **한 번에** 반환: 시간표 기준 전체 셀(세션 미생성 타임 포함),
  셀별 수업 종류·예약 n/정원·1:1 예약 여부. **명단은 포함하지 않는다**
- 셀별 예약자 명단은 **셀 클릭 시 별도 API**로 조회
- 모바일 일 단위 뷰는 **별도 API 없이** 주간 응답을 FE가 잘라 쓴다

## Claude's Discretion

- **`ClassSession` 실체화 시점** — 필요할 때 생성(첫 예약·휴강 시). 사용자가 명시적으로 위임
- **동시성 보장 구현 방식** — D-021에 따라 DB 제약 + 조건부 UPDATE 우선, 낙관적 락 미사용
- **`PassTransaction` 회원 주체 컬럼 추가** — ROADMAP D-030 노트가 예고한 스키마 확장
- **예약↔이용권 연결** — 예약 행이 차감한 `pass_id` 보유
- 새 enum·에러코드 구성, 패키지 구조, DTO 형태, 인덱스 설계
- 세션 미생성 타임의 "0/10" 계산을 조회 쿼리에서 합치는 방법

## Deferred Ideas

- 날짜별 시간 조정("그날만 시간 옮기기") — `ClassSession`에 시각 복사로 여지만 확보
- 일회성 임시 수업 추가 — 예약·정원·휴강 경로가 두 갈래가 됨
- 관리자 시간표 CRUD API — 시간표가 자주 바뀌는 운영이 되면 별도 phase
- 정원 초과 대기(waitlist) — requirements §6에서 이미 MVP 제외
- 회원용 알림 — 조회 경로가 요구사항에 없음. 웹 푸시와 함께 v2
- 휴강 철회 시 예약 자동 복원 — 잔여 음수 위험으로 기각
- 관리자 오버부킹 — Core Value 위배로 기각
