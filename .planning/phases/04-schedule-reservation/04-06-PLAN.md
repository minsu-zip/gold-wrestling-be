  <behavior>
    **ReservationPassPolicy (순수 판정, object)**
    · `requiredPassType(ClassType.SESSION)` → `PassType.SESSION_PASS`
    · `requiredPassType(ClassType.LESSON)` → `PassType.LESSON_PASS`
    · `requiredPassType(ClassType.EVENING)` → `ClassSessionNotReservableException` (저녁반은 예약 대상이 아니다)
    · `DEDUCTION_AMOUNT` = `BigDecimal("1.0")` — 예약 1건의 차감량. 복구는 이 값의 `negate()`
    · `selectCandidate(candidates: List<Pass>)` → 리스트가 비어 있으면 `InsufficientPassCountException`,
      아니면 `candidates.first()` (쿼리가 이미 정렬해 내려준다 — 서비스가 다시 정렬하지 않는다)

    **PassRepository.findDeductionCandidates(memberId, type, classDate, requiredAmount)**
    · `status = ACTIVE`인 이용권만 (등록 취소된 것은 제외)
    · `endDate >= classDate` — **수업 날짜 기준** 만료 판정. `Pass.isExpired`(D-066 종료일 포함)와 같은 비교축
    · `remainingCount >= requiredAmount` — **단일 이용권 기준**. 여러 장 합산 금지의 실현부
    · 정렬 `order by p.endDate asc, p.id asc` — 만료 임박순, 동률이면 결정적 순서
    · 다른 회원의 이용권은 절대 포함되지 않는다 (`p.member.id = :memberId`)

    **경계 케이스 (테스트에서 반드시 다룰 것)**
    · 잔여 1.0 한 장 + 잔여 0.5 한 장 → 후보는 1.0짜리 한 장뿐
    · 잔여 0.5 두 장 → 후보 0건 → `InsufficientPassCountException` (합산 금지, RESV-03)
    · `endDate == classDate` → 후보에 포함된다 (종료일 당일까지 사용 가능, D-066)
    · `endDate == classDate.minusDays(1)` → 제외된다
    · 오늘은 유효하지만 수업날에는 만료되는 이용권 → **제외된다** (예약일 기준이 아님을 증명하는 핵심 케이스)
    · `status = CANCELED` 이용권 → 잔여가 남아 있어도 제외된다
    · `SESSION_PASS`만 보유한 회원의 `LESSON` 예약 → 후보 0건
    · 잔여 1.0 두 장(endDate 다름) → `endDate`가 빠른 쪽이 첫 번째
    · 잔여 1.0 두 장(endDate 동일) → `id`가 작은 쪽이 첫 번째
  </behavior>
