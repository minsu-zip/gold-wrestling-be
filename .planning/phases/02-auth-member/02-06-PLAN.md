  <action>
**KakaoTokenResponse.kt / KakaoUserResponse.kt** — 카카오 응답 매핑용 **외부 계약 DTO**다. 우리 API DTO가
아니므로 `auth/dto`가 아니라 `auth/kakao` 패키지에 둔다(구분이 흐려지면 실수로 응답에 노출된다). KDoc에 그 구분을 남긴다.
- `KakaoTokenResponse`: `accessToken`(카카오 JSON 키 `access_token`), `tokenType`, `expiresIn`, `refreshToken`, `scope`.
  카카오는 snake_case를 쓰므로 필드 매핑이 필요하다 — 클래스에 `@JsonNaming(SnakeCaseStrategy)` 또는 필드별
  `@JsonProperty("access_token")` 중 하나를 쓴다. **Boot 4는 Jackson 3(`tools.jackson`)이므로 임포트 경로를
  verify-boot4-api 절차로 확인한 뒤 적용한다.** 카카오의 refresh 토큰은 우리가 쓰지 않으므로(우리는 자체
  refresh를 발급한다) 필드로 받되 어디에도 저장하지 않는다 — 그 이유를 KDoc에 남긴다
- `KakaoUserResponse`: `id: Long`, `connectedAt: String?`. **`kakao_account`·`properties`를 매핑하지 않는다** —
  카카오는 인증 수단으로만 쓰고 실명·전화번호는 온보딩으로 받는다(D-025). 이 제약을 KDoc에 명시한다

**KakaoExceptions.kt** — `DomainException` 상속 두 개.
- `class KakaoAuthFailedException : DomainException(ErrorCode.KAKAO_AUTH_FAILED, "카카오 로그인에 실패했습니다. 다시 시도해 주세요.")`
- `class KakaoUnavailableException : DomainException(ErrorCode.KAKAO_UNAVAILABLE, "카카오 서버와 통신하지 못했습니다. 잠시 후 다시 시도해 주세요.")`
사용자 대면 문구만 담는다. 원인 예외는 `cause`로 넘기지 않는다 — `DomainException`이 message만 노출하므로 안전하지만,
서버 로그에는 원인을 남긴다.

**KakaoApiClient.kt** — `@Component`. 생성자 주입: `@Qualifier("kakaoRestClient") RestClient`, `KakaoProperties`.
**`@Transactional`을 붙이지 않는다** — 이 클래스는 DB를 만지지 않으며, 호출부도 트랜잭션 밖에서 부른다.
- `fun exchangeToken(code: String): KakaoTokenResponse` —
  `kakaoProperties.tokenUri`로 POST, `MediaType.APPLICATION_FORM_URLENCODED`,
  본문에 `grant_type=authorization_code`, `client_id=restApiKey`, `redirect_uri=redirectUri`, `code`, `client_secret`.
  **`redirect_uri`는 요청 파라미터가 아니라 프로퍼티에서 읽는다** (D-046)
- `fun fetchKakaoId(kakaoAccessToken: String): Long` —
  `kakaoProperties.userInfoUri`로 GET, `Authorization: Bearer <kakaoAccessToken>` 헤더. 응답의 `id`를 반환
- 두 메서드 모두 `.retrieve()`에 상태 핸들러를 걸어 4xx → `KakaoAuthFailedException`,
  5xx → `KakaoUnavailableException`으로 바꾼다. `RestClientException`(연결 실패·타임아웃)도 잡아
  `KakaoUnavailableException`으로 바꾼다
- 로깅: `logger.warn`으로 실패 사실과 HTTP 상태만 남긴다. **인가 코드·client_secret·카카오 액세스 토큰을 로그에 남기지 않는다.**
  응답 본문도 그대로 로깅하지 않는다(카카오 에러 본문에 요청 파라미터가 반사될 수 있다)
- 정확한 상태 핸들러 API(`onStatus` 시그니처)는 Boot 4/Spring Framework 7 기준으로 verify-boot4-api 절차로 확인한다

**KakaoApiClientTest.kt** — 네트워크 없이 검증한다. `MockRestServiceServer`는 `RestClient.Builder`에 bind 하므로
스프링 컨텍스트를 띄우지 않는 **순수 단위테스트**로 만들 수 있다: 테스트 안에서 `RestClient.builder()`를 만들고
`KakaoApiMockSupport.bindKakaoMock(builder)`로 목 서버를 붙인 뒤 `KakaoApiClient(builder.build(), kakaoProperties)`를 직접 생성한다.
`kakaoProperties`는 테스트용 더미 값(`restApiKey = "test-rest-api-key"` 등)으로 만든다 — 실값처럼 보이는 문자열 금지.
요청 본문 검증은 `MockRestRequestMatchers.content().formData(...)` 또는 `content().string(containsString("grant_type=authorization_code"))`로 한다.
위 behavior 전부를 백틱 한국어 서술문 테스트로 옮긴다.
