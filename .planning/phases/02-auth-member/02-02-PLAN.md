`AuthRepositoryIntegrationTest.kt`는 기존 통합테스트와 **동일한 애노테이션 조합**(`@SpringBootTest` +

제약 위반 검증은 `assertThatThrownBy { ... }`로 감싸고, JPA는 flush 시점에 예외를 던지므로 저장 후
`entityManager.flush()` 또는 `repository.saveAndFlush(...)`를 호출해 예외를 그 자리에서 받는다.
테스트 간 데이터 격리는 `@Transactional` 롤백을 쓴다(동시성 테스트가 아니므로 허용 — add-domain-test §2).
단, 제약 위반 테스트는 트랜잭션을 오염시키므로 각 검증을 `assertThatThrownBy` 하나로 끝내고
같은 트랜잭션에서 추가 저장을 시도하지 않는다.
`Clock` 의존이 필요한 곳(`createdAt`, `expiresAt`)은 테스트에서 고정 `OffsetDateTime` 상수를 직접 넘긴다 —
`OffsetDateTime.now()`를 부르지 않는다(conventions §10.3).

- `member 테이블에 kakao_id 유니크 제약과 rejection_reason 컬럼이 있다`, `refresh_token 테이블에 주체 배타
  CHECK 제약이 있다` 두 테스트를 추가한다. 조회는 기존 테스트와 같은 방식(`JdbcClient` + `information_schema`)을

  이고 `constraint_type = 'CHECK'`인 행 수가 1인지 확인한다
