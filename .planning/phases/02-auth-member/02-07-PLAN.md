**PasswordEncoderConfig.kt** — `@Configuration` + `@Bean fun passwordEncoder(): PasswordEncoder = PasswordEncoderFactories.createDelegatingPasswordEncoder()`.
KDoc에 D-045 근거를 남긴다: 저장 값이 `{bcrypt}` 접두로 알고리즘을 기술하므로 나중에 알고리즘을 바꿔도
기존 해시를 그대로 검증할 수 있다. 그래서 `admin.password_hash`가 `VARCHAR(100)`이다.
정확한 클래스 위치(`org.springframework.security.crypto.factory.PasswordEncoderFactories`)는
verify-boot4-api 절차의 컴파일 검증으로 확정한다.

**dto/AdminLoginRequest.kt** — `data class AdminLoginRequest(@field:NotBlank @field:Size(max = 50) val loginId: String, @field:NotBlank @field:Size(max = 100) val password: String)`.
`@Schema`로 설명을 붙이되 예시 값에 실값처럼 보이는 문자열을 쓰지 않는다.

**dto/AdminLoginResponse.kt** — `data class AdminLoginResponse(tokens: TokenPairResponse, admin: AdminSummary)`와
같은 파일 안의 `data class AdminSummary(adminId: Long, name: String)`.
`passwordHash`·`loginId`를 응답에 담지 않는다 — `loginId`는 로그인 화면에 되돌려줄 이유가 없다.

**AdminAuthService.kt** — `@Service`, 클래스에 `@Transactional(readOnly = true)`.
토큰 발급은 `TokenService`의 `@Transactional` 메서드가 자기 트랜잭션에서 처리하므로 이 서비스는 조회만 한다.
생성자 주입: `AdminRepository`, `PasswordEncoder`, `TokenService`.
- `fun login(loginId: String, rawPassword: String): AdminLoginResponse`
  1. `adminRepository.findByLoginId(loginId)` — 없으면 `InvalidCredentialsException`
  2. `passwordEncoder.matches(rawPassword, admin.passwordHash)`가 false면 같은 예외
  3. `tokenService.issueTokenPair(PrincipalType.ADMIN, admin.id!!)`
  4. `AdminLoginResponse(TokenPairResponse.from(pair), AdminSummary(admin.id!!, admin.name))`
  **1과 2가 완전히 같은 예외·같은 메시지를 던져야 한다** — 계정 열거(어느 loginId가 존재하는지) 공격을 막는다.
  이 의도를 KDoc에 명시한다.
  예외 클래스 `InvalidCredentialsException`은 **이 파일 안에** `DomainException` 하위로 선언한다
  (02-04가 소유한 `auth/AuthExceptions.kt`를 이 플랜이 수정하면 파일 소유권이 겹친다).
  메시지는 "아이디 또는 비밀번호가 올바르지 않습니다." 하나만 쓴다.
  실패 시 `logger.warn`으로 `loginId`만 남긴다 — **비밀번호는 로그에 남기지 않는다.**
