**헤더**: `#!/usr/bin/env bash`, 파일 설명 2줄(무엇을 하는 스크립트인지 + 근거 `decisions.md`/`REQUIREMENTS.md INFRA-06` 참조), `set -euo pipefail`. 실행 방법(`ssh ubuntu@<host> 'bash -s' < deploy/server-setup.sh`)과 "**두 번 실행해도 안전하다**"는 사실을 헤더 주석에 명시한다.

**블록 5개, 각각 멱등 가드 포함** — 블록마다 무엇을 하는지 한국어 주석 1줄 + 스킵 조건을 밝힌다:
1. **Docker Engine + compose 플러그인** — `command -v docker` 가드. 없을 때만 공식 apt 저장소 절차(keyring 설치 → `docker.list` 작성 → `apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`). `$(. /etc/os-release && echo "$VERSION_CODENAME")`로 코드네임을 동적으로 넣어 Ubuntu 버전을 하드코딩하지 않는다.
2. **스왑 2GB** — `swapon --show | grep -q '/swapfile'` 가드로 생성 스킵, `grep -q '/swapfile' /etc/fstab ||` 가드로 fstab 중복 추가 방지. 두 가드가 별개인 이유(스왑은 켜져 있지만 fstab에 없어 재부팅 후 사라지는 상태가 실재한다)를 주석으로 남긴다.
3. **타임존** — `timedatectl set-timezone Asia/Seoul`. 연산 자체가 멱등이라 가드가 없다는 사실을 주석으로 밝힌다(CLAUDE.md 시간대 규칙).
4. **docker 그룹 가입** — `usermod -aG docker ubuntu`. 역시 멱등. 이 변경은 **재로그인해야 적용된다**는 점을 스크립트 종료 메시지에 안내한다.
5. **배포 디렉토리** — `mkdir -p /opt/gold-wrestling/backups`, `chown -R ubuntu:ubuntu /opt/gold-wrestling`, `[ -f /opt/gold-wrestling/.env ] || touch /opt/gold-wrestling/.env`. **`.env`는 없을 때만 만든다 — 절대 덮어쓰지 않는다**(시크릿 소실 방지). `backups/`는 Phase 9 자리라는 주석. git clone·git init을 하지 않는다 (D-18).

**종료 요약 출력** — 스크립트 끝에서 현재 상태를 사람이 읽을 수 있게 출력한다: `docker --version`, `docker compose version`, `swapon --show`, `timedatectl | grep 'Time zone'`, `ls -la /opt/gold-wrestling`. 07-06이 "2회 실행 결과가 같다"를 판정할 때 이 출력을 비교 대상으로 쓴다 — 그러므로 **실행 시각처럼 매번 달라지는 값을 출력에 섞지 않는다.**

파일 실행 권한을 준다(`chmod +x deploy/server-setup.sh`).

**첫머리 인용구**: 이 문서가 운영 환경변수·메모리 예산·서버 세팅·수동 배포 절차의 정본이라는 것, 값의 "왜"는 `decisions.md` D-169~D-175에 있다는 것, 운영 `.env`는 서버에만 존재하고 레포 밖이라는 것.

**`## 1. 운영 환경변수 (INFRA-07)`** — `| 키 | 의미 | 예시/기본값 | 출처·주의 |` 4열 표. `.env.example`의 **모든 키**를 빠짐없이 싣는다(DB·서버·JWT·카카오·CORS·관리자 시드·배치·기본 지점·운영 배포 섹션 전부). 운영에서 로컬과 값이 달라야 하는 키는 별도로 표시한다:
- `KAKAO_REDIRECT_URI` = `https://app.goldwrestling.com/login/callback` (REQUIREMENTS.md INFRA-07 명시값)
- `CORS_ALLOWED_ORIGINS` = `https://app.goldwrestling.com`
- `SWAGGER_ENABLED=false` (운영), `DOMAIN`=API 도메인, `DB_HOST=postgres`(compose 서비스명)
- `BATCH_INACTIVITY_SCHEDULER_ENABLED=false` — 기본 꺼짐 유지가 의도이며 켜는 판단은 배포 후 D-130 절차로 한다 (D-116·D-121·D-151)
- `ADMIN_SEED_*` — 최초 1회만 채우고 이후 비운다 (D-038)
**실제 시크릿 값은 쓰지 않는다.** `JWT_SECRET`·`DB_PASSWORD`·`KAKAO_*`는 "생성 방법"만 적는다(예: `openssl rand -base64 48`).

**`## 2. 메모리 예산 (INFRA-05, D-06)`** — 스왑 2GB 전제와 t3.micro RAM 1GB를 밝히고 `| 대상 | limit | 실측 RSS | 여유 | 비고 |` 5열 표:
- app 550M / postgres 300M / caddy 50M — 합계 900M, 나머지 ~124M이 OS+dockerd 몫이라는 계산을 표 아래에 명시
- **실측 RSS·여유 열은 `(미측정 — 07-06 실서버 배포에서 기입)`으로 비워 둔다.** 07-06이 이 칸을 채운다
- JVM 배분(`MaxRAMPercentage=60` → 힙 ≈330M / 비힙 ≈220M)과 그 근거·재조정 기준(`docker stats` 실측 후 확정, D-07/D-173)
- postgres 파라미터(`shared_buffers=64MB` 등)와 `max_connections=20`의 근거, 부하테스트(Phase 10)에서 재조정 대상이라는 것 (D-11)
- Caddy 50M에 대한 주의: 장시간 구동 시 메모리가 증가한다는 **단일 커뮤니티 보고(신뢰도 LOW, 원인 미확정)**가 있어 배포 직후뿐 아니라 몇 시간 뒤에도 `docker stats`를 한 번 더 본다. 부족하면 50M 자체를 재조정 대상으로 삼고 `caddy:2-alpine` 전환을 검토한다 — 확정 사실이 아니라 관찰 항목으로 적는다

**`## 3. 서버 초기 세팅 (INFRA-06, D-18)`** — 실행 명령(`ssh ubuntu@<host> 'bash -s' < deploy/server-setup.sh`), 스크립트가 하는 일 5가지, **재로그인이 필요한 이유**(docker 그룹), 서버 디렉토리 구조(`/opt/gold-wrestling/`에 `compose.prod.yml`·`Caddyfile`·`.env`·`backups/`만, git 없음), 파일 전달 방법(`scp` — Phase 8이 자동화), 두 번 실행해도 안전하다는 것과 그 확인 방법.
