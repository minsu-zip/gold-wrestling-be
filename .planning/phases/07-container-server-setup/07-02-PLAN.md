**측정 절차** (임시 파일은 레포 밖 `/tmp`에 만들고 커밋하지 않는다):

1. **fat jar 비교본 빌드** — `/tmp/Dockerfile.fatjar`에 레이어 추출 없이 `COPY --from=builder /builder/build/libs/*.jar application.jar` 한 줄로 끝나는 단일 레이어 런타임을 만들어 `docker build -f /tmp/Dockerfile.fatjar -t gw-be:fatjar .`로 빌드한다. 베이스·비루트·ENTRYPOINT는 정본 Dockerfile과 동일하게 맞춘다(변수 통제).
2. **이미지 크기 비교** — `docker image ls --format '{{.Repository}}:{{.Tag}} {{.Size}}' | grep gw-be`로 두 이미지 크기를 기록한다.
3. **레이어 구성 비교** — `docker history --no-trunc --format '{{.Size}}\t{{.CreatedBy}}' gw-be:test`와 `... gw-be:fatjar`로 각 이미지의 레이어별 크기를 기록한다. 레이어드 쪽은 `application` 레이어가 수 MB 수준, fat jar 쪽은 단일 레이어가 수십~수백 MB여야 한다.
4. **코드만 바뀐 재배포 전송량** — 소스 파일 하나에 무해한 변경(예: 기존 Kotlin 파일의 주석 한 줄 추가)을 넣고 두 이미지를 각각 재빌드한 뒤, **바뀐 레이어들의 크기 합**을 `docker history`로 계산한다. 이것이 "코드만 바뀐 재배포에서 서버가 새로 pull해야 하는 바이트"의 근사치다. 측정이 끝나면 **소스 변경을 되돌린다**(`git checkout -- <파일>`), 커밋에 남기지 않는다.
