**app 서비스**:

**(a) `deploy/Caddyfile`** — 07-RESEARCH.md Pattern 4 골격을 그대로 쓴다:
- 전역 옵션 블록에 `email {$ACME_EMAIL}` (Let's Encrypt 만료 알림, D-19)
- 사이트 블록 주소는 `{$DOMAIN:localhost}` — env 미설정 시 localhost로 떨어져 로컬 검증이 가능하다 (D-05/D-19). `http://` 접두를 붙이지 않는다 — 붙이면 자동 HTTPS가 꺼진다
- named matcher `@blocked-actuator`: `path /actuator/*` + `not path /actuator/health`. 이어서 `respond @blocked-actuator 404` (D-20). **`/actuator/info`를 포함해 health 외 전부 차단**이다
- `reverse_proxy app:8080` — 서비스명 `app`은 compose 내부 DNS로 해석된다
- 매처 순서가 의미를 가지므로(먼저 선언된 respond가 프록시보다 앞서야 차단이 성립) 그 이유를 한국어 주석으로 남긴다
- `auto_https` 지시어를 명시적으로 켜지 않는다 — 도메인이 있는 사이트 주소면 기본 동작이다. 그 사실 자체를 주석으로 남겨 나중에 "왜 설정이 없지?"를 방지한다

**(b) `deploy/compose.local.yml`** — 실서버 없이 운영 compose를 그대로 띄워 보기 위한 최소 오버라이드 (D-05). 오버라이드는 **작을수록 좋다** — 운영과 로컬 차이가 클수록 사전 검증의 의미가 줄어든다. 포함할 것:
- `app.image`를 로컬 빌드 태그(`gw-be:test`, 07-02 Task 1 산출물)로 치환 — GHCR에 아직 이미지가 없으므로 필수
- caddy에 `command`로 로컬 인증서 모드를 켠다: Caddy가 `localhost` 사이트에 대해 내부 CA로 인증서를 발급하도록 `CADDY_` 관련 환경변수 대신 **Caddyfile 전역 옵션 `local_certs`를 오버라이드로 주입**한다. 방법은 재량이나 **`deploy/Caddyfile` 본문을 로컬 전용으로 오염시키지 않는 방식**이어야 한다 — 예: 로컬 전용 Caddyfile 조각을 이 오버라이드에서 bind mount로 교체. 선택한 방식을 파일 상단 주석에 근거와 함께 적는다
- 로컬에서 앱을 직접 찔러 볼 수 있도록 app에 호스트 포트를 하나 노출(예: `18080:8080`)해도 된다 — 운영에는 없는 설정이라는 것을 주석에 명시
- 파일 상단에 실행 방법 두 줄: `cp -n .env.example deploy/.env` (최초 1회, 임시값 채움) → `docker compose -f deploy/compose.prod.yml -f deploy/compose.local.yml --env-file deploy/.env up -d`. **`deploy/.env`인 이유**(service `env_file:`은 project directory=`deploy/` 기준)를 주석에 한 줄 적는다

두 파일 모두 실도메인·실이메일·시크릿을 넣지 않는다.
