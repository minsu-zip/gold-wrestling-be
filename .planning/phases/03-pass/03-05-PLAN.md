  <behavior>
    **A. `fun changePeriod(newStartDate: LocalDate?, newEndDate: LocalDate)`**

    `newStartDate`가 null이면 기존 시작일을 유지한다. 검사 순서: 취소 여부 → 타입별 시작일 수정 가능 여부 → 기간 유효성.
    변경 전 값은 **호출부(서비스)가 이 메서드 호출 전에 지역 변수로 보관**한다 — 이 메서드는 반환값이 없다.

    | 이용권 | 입력 | 기대 |
    |---|---|---|
    | `EVENING_MEMBERSHIP` 2026-03-01~2026-04-01 | start=2026-03-15, end=2026-05-15 | 두 값 모두 반영 |
    | `SESSION_PASS` 2026-03-01~2027-02-28 | start=null, end=2027-06-30 | 종료일만 반영, 시작일 유지 |
    | `SESSION_PASS` 2026-03-01~ | start=2026-04-01(기존과 다름) | `InvalidPassPeriodException` (D-062 횟수권 시작일 고정) |
    | `SESSION_PASS` 2026-03-01~ | start=2026-03-01(기존과 동일) | 허용 — 같은 값 재전송은 변경이 아니다 |
    | `EVENING_MEMBERSHIP` 2026-03-01~ | start=null, end=2026-02-01 | `InvalidPassPeriodException` (종료일 < 시작일) |
    | `SESSION_PASS`, `endDate` 2020-01-01(만료됨) | end=2027-12-31 | 허용 — 만료권 유효기간 연장 (D-056, PASS-07) |
    | `status = CANCELED` | 아무 값 | `PassAlreadyCanceledException` |

    **B. `fun cancel(reason: String, admin: Admin, now: OffsetDateTime): BigDecimal`**

    반환값은 **원장에 기록할 상쇄 수량**이다(0이면 서비스가 이력을 남기지 않는다, D-065).
    **잔여 횟수를 직접 바꾸지 않는다** — 잔여 0 반영은 `PassRepository.zeroRemainingCount` 조건부 UPDATE의 몫이다
    (03-03의 `validateAdjustment` ↔ `adjustRemainingCount`와 같은 역할 분리).

    | 이용권 | 기대 반환 | 기대 상태 |
    |---|---|---|
    | `SESSION_PASS` 잔여 3.0 | `-3.0` | `status=CANCELED`, `canceledAt=now`, `cancelReason=reason`, `canceledBy=admin` |
    | `SESSION_PASS` 잔여 0 | `0` | 위와 동일 (이력은 남기지 않는다, D-065) |
    | `LESSON_PASS` 잔여 0.5 | `-0.5` | 위와 동일 |
    | `EVENING_MEMBERSHIP` | `0` | 위와 동일 (기간제는 수량 개념 없음) |
    | `SESSION_PASS` 잔여 3.0 | — | 호출 후에도 `remainingCount`는 3.0 그대로 (반영은 조건부 UPDATE 담당) |
    | `status = CANCELED` | — | `PassAlreadyCanceledException` |
    | `reason`이 공백 문자열 | — | `InvalidPassPeriodException`이 아니라 서비스/DTO의 `@NotBlank` 책임 — 이 메서드는 `reason.trim()` 결과를 그대로 저장한다 |
  </behavior>
  <implementation>
    `changePeriod`는 `val resolvedStart = newStartDate ?: startDate`로 시작일을 확정한 뒤,
    횟수제(`type != EVENING_MEMBERSHIP`)이면서 `resolvedStart != startDate`인 경우를 거부한다.
    `newEndDate.isBefore(resolvedStart)`이면 거부한다 — 같은 날(당일 시작·종료)은 허용한다.
    `cancel`은 `status = PassStatus.CANCELED`, `canceledAt = now`, `cancelReason = reason.trim()`, `canceledBy = admin`을
    대입하고 `remainingCount?.negate() ?: BigDecimal.ZERO`를 반환한다.
    두 메서드 모두 KDoc에 근거 결정 번호(D-056/D-057/D-059/D-062/D-065)와
    "이력은 호출부가 같은 트랜잭션에서 남긴다"는 계약을 명시한다.
  </implementation>
</feature>
