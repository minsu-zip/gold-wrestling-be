  <behavior>
    **A. `Pass.Companion.register(member, branch, type, startDate, term, initialCount, registeredBy, now): Pass`**

    `term: EveningMembershipTerm?`은 기간제 전용, `initialCount: BigDecimal?`은 횟수제 전용이다.
    `startDate` 기본값(오늘) 채우기는 **서비스가 `Clock`으로** 하고 이 팩토리는 항상 확정된 날짜를 받는다.
    종료일 계산식과 "종료일 당일 포함" 여부는 **`docs/decisions.md` D-066에 확정된 식을 그대로 쓴다** —
    이 플랜은 식을 다시 정하지 않는다.

    | 입력 | 기대 |
    |---|---|
    | `SESSION_PASS`, `startDate=2026-03-01`, `initialCount=10.0` | `endDate`가 D-066의 1년 계산식 결과, `remainingCount=10.0`, `status=ACTIVE` |
    | `LESSON_PASS`, `startDate=2026-03-01`, `initialCount=5.0` | 횟수권과 동일한 1년 계산 |
    | `EVENING_MEMBERSHIP`, `ONE_MONTH`, `startDate=2026-03-01` | `endDate`가 D-066의 1개월 계산식 결과, `remainingCount=null` |
    | `EVENING_MEMBERSHIP`, `THREE_MONTHS` / `SIX_MONTHS` | 각각 3·6개월 계산식 결과 |
    | `SESSION_PASS`, `startDate`가 과거(2025-01-01) | 예외 없음 — 과거 시작일 허용 (D-055) |
    | `SESSION_PASS`, `initialCount=0.3` | `InvalidAdjustmentUnitException` |
    | `SESSION_PASS`, `initialCount=0` 또는 음수 | `InvalidAdjustmentUnitException` |
    | `EVENING_MEMBERSHIP`, `initialCount=5.0` 지정 | `PassTypeNotAdjustableException` (기간제는 횟수 개념이 없다) |
    | `EVENING_MEMBERSHIP`, `term=null` | `InvalidPassPeriodException` |
    | `SESSION_PASS`, `term` 지정 | `InvalidPassPeriodException` (횟수권에 회비 기간 단위는 의미가 없다) |
    | 등록 직후 상태 | `status=ACTIVE`, `canceledAt`·`cancelReason`·`canceledBy` 전부 null |

    **B. `Pass.displayStatus(today: LocalDate): PassDisplayStatus`**

    우선순위: 취소 → 만료 → 소진 → 사용가능.

    | 이용권 | today | 기대 |
    |---|---|---|
    | `status=CANCELED`, 잔여 5.0, 기간 내 | 기간 내 | `CANCELED` (잔여가 남아도 취소가 우선) |
    | `SESSION_PASS` 잔여 5.0, `endDate`가 과거 | 만료 후 | `EXPIRED` |
    | `SESSION_PASS` 잔여 5.0, `today == endDate` | 종료일 당일 | D-066의 유효 판정식이 정하는 값 (테스트 메서드명에 그 판정을 서술한다) |
    | `SESSION_PASS` 잔여 0, 기간 내 | 기간 내 | `EXHAUSTED` |
    | `SESSION_PASS` 잔여 0, `endDate` 과거 | 만료 후 | `EXPIRED` (만료가 소진보다 우선) |
    | `EVENING_MEMBERSHIP`, 기간 내 | 기간 내 | `USABLE` (기간제는 소진 개념이 없어 `EXHAUSTED`가 될 수 없다) |
    | `SESSION_PASS` 잔여 2.0, 기간 내 | 기간 내 | `USABLE` |
  </behavior>
  <implementation>
    `register`는 `Pass`의 companion object에 둔다. 타입별 분기는 `when (type)` 하나로 모아
    "이 타입에 무엇이 필수이고 무엇이 금지인지"가 한 화면에 보이게 한다.
    초기 횟수 검증은 03-03의 `HALF_SESSION` 상수를 재사용해 `remainder(HALF_SESSION).compareTo(ZERO) != 0` 로 하고,
    양수 여부는 `compareTo(BigDecimal.ZERO) <= 0` 로 판정한다 (`equals` 금지, D-016).
    `displayStatus`는 `when { status == CANCELED -> ...; isExpired(today) -> ...; isExhausted() -> ...; else -> USABLE }`
    형태의 단일 `when`으로 우선순위를 코드 모양으로 드러낸다. `isExpired(today)`·`isExhausted()`는
    private 헬퍼로 두되, 만료 판정식은 D-066을 인용한 KDoc을 붙인다 (Phase 5 만료 배치가 이 식을 재사용한다).
    `displayStatus`는 `today`를 파라미터로 받는다 — 엔티티가 `Clock`에 의존하지 않아야 스프링 없이 테스트된다.
  </implementation>
</feature>
